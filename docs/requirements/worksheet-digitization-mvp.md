# 试卷图片电子化 MVP 需求简报

## 目标

- 问题：老师手中的纸质试卷或练习题常带有拍摄透视、阴影、手写作答和浅色水印，直接分享或打印会影响学生使用；逐页人工修图和合并文件又耗时。
- 期望结果：老师可在桌面浏览器中一次导入最多 20 张照片，完成裁边、角度纠正、画面增强、常见手写/水印擦除和人工补修，并导出为适合电脑、手机查看及 A4 打印的单个 PDF 文件。
- 参与者：主要用户为教师；最终产物的使用者为学生；产品初版不区分管理员或其他账号角色。
- 成功信号：使用约定的 8–12 张代表性真实样张验收时，至少 80% 的页面可在每页不超过 60 秒人工补修后成为可打印页面；20 页任务可完整导出且顺序正确；最终页面不丢失题干、选项、公式、表格线或插图中的关键信息。

## 术语

- **电子版**：每张处理后的试卷图片作为一页封装进 PDF；初版不是可编辑、可搜索或可复制文字的文档。
- **文字增强**：提亮纸张、压低阴影、加深印刷文字和提高可读性，不添加荧光色标记。
- **智能擦除**：自动生成可撤销的擦除建议，重点覆盖黑、蓝、红色手写笔迹和浅色水印。手写识别不能只依赖颜色差异，还应结合笔画形态、连通结构和版面上下文区分手写内容与印刷内容；低置信度区域由老师复核和补修。
- **恢复笔**：将局部区域恢复为自动处理前的图像内容，而非生成新的内容。

## 范围

### 包含

- 无需登录的 Chrome/Edge 桌面 Web 应用。
- 1–20 张图片的批量导入、校验、排序、旋转、删除、逐页处理和失败重试。
- 自动纸张边界检测、裁边、旋转与透视/倾斜纠正；提供四角手动校正。
- 纸张增白、阴影抑制、印刷文字增强，以及彩色/黑白结果选择。
- 黑、蓝、红手写笔迹与浅色水印的本地智能擦除建议；黑色手写作为核心识别场景，并提供低置信度提示。
- 可调大小橡皮擦、恢复笔、撤销/重做和处理前后对比。
- A4 PDF 打印预览、页边距和清晰/标准/小文件三档导出质量。
- 浏览器内临时任务恢复、主动清空和自动过期清理。

### 非目标

- OCR、文字录入、可搜索 PDF、Word 导出、公式识别或题目结构化。
- 题目切分、答案搜索、相似题、错题本、知识点标签或长期题库。
- 注册登录、跨设备同步、历史任务中心、链接/二维码分享或云端协作。
- 手机浏览器、Safari、Firefox、小程序或原生应用适配。
- 保证自动去除与印刷内容严重重叠、形态高度相似或造成原题不可恢复遮挡的全部手写内容，以及复杂印章或覆盖正文的深色水印。
- 在没有权利或授权的情况下移除第三方权利标识或再分发受保护材料。

## 功能需求

| ID | 需求 | 优先级 | 验证方式 |
| --- | --- | --- | --- |
| FR-1 | 应用应支持一次选择或拖入 1–20 个 JPG、JPEG、PNG 或 WebP 文件；单文件上限 20 MB。 | 必须 | 组件测试；批量导入 E2E |
| FR-2 | 导入前应校验文件类型、大小和可解码性；不合格文件应逐个说明原因，合格文件仍可继续进入任务。 | 必须 | 无效文件与部分成功 E2E |
| FR-3 | 每个文件应成为独立页面；重复文件允许作为不同页面导入，页面默认保持用户选择顺序。 | 必须 | 顺序与重复文件测试 |
| FR-4 | 页面缩略图列表应显示状态与进度，并支持拖拽排序、左/右旋转、删除和单页重试；一页失败不得中止其他页面。 | 必须 | 批处理与失败隔离 E2E |
| FR-5 | 系统应自动检测纸张边界并完成裁边、方向和透视纠正；无法可靠检测时应保留原图并提示用户调整四角。 | 必须 | 倾斜、缺角、复杂背景样张测试 |
| FR-6 | 用户应能拖动四个角重新定义纸张边界，预览确认后重新执行透视纠正；取消时不得覆盖上次结果。 | 必须 | 四角编辑交互测试 |
| FR-7 | 系统应提供自动增强结果，至少包含纸张增白、阴影抑制、印刷文字加深，并允许彩色与黑白模式切换。 | 必须 | 低对比、阴影、彩色图表样张测试 |
| FR-8 | 系统应以手写/印刷内容分类为主要依据、颜色为辅助特征，针对黑、蓝、红手写笔迹和浅色水印生成智能擦除建议。系统应显示处理进度；低置信度或可能伤及印刷内容的区域应被标记为待复核，不能仅因笔迹为黑色而跳过识别。 | 必须 | 分颜色标注样张、印刷/手写混淆与低置信度测试 |
| FR-9 | 智能擦除不得不可逆地覆盖原图；用户应能在原图与当前结果之间进行滑杆或并排对比，并恢复任意局部区域。 | 必须 | 像素恢复与对比交互测试 |
| FR-10 | 编辑器应提供可调笔刷大小的橡皮擦和恢复笔，以及至少 20 步撤销/重做；切换页面后操作历史在当前任务内仍应保留。 | 必须 | 编辑历史与跨页状态测试 |
| FR-11 | 用户应能取消尚未完成的单页或整批处理；取消后已成功页面保留，未完成页面可再次启动。 | 应该 | 取消与重试集成测试 |
| FR-12 | 导出前应展示 A4 PDF 预览，并提供彩色/黑白、页边距和“清晰/标准/小文件”质量档位；每个未删除页面对应一页 PDF。 | 必须 | PDF 页面、尺寸与配置测试 |
| FR-13 | PDF 应按缩略图列表的最终顺序生成，保持页面宽高比并居中放置，不裁掉试卷内容；文件名可由用户修改。 | 必须 | PDF 像素与元数据检查 |
| FR-14 | 导出前存在失败或待复核页面时，系统应明确列出并要求用户确认；确认不应被解释为页面质量已自动通过。 | 必须 | 风险确认 E2E |
| FR-15 | 当前任务应保存在浏览器本地并能在意外刷新后恢复；用户可一键清空，超过 24 小时未活动的任务应自动删除。 | 应该 | IndexedDB 恢复与过期测试 |

## 质量属性

- **性能（NFR-1）**：在基准环境（8 GB 内存、4 核 CPU、最新稳定版 Chrome/Edge、约 12 MP 单页照片）中，首张缩略图应在导入后 3 秒内出现；页面处理期间主界面应保持可交互；20 页批量任务不得因应用自身内存失控而崩溃。智能处理耗时应逐页反馈，不以固定完成秒数作为初版质量承诺。
- **安全与隐私（NFR-2）**：初版图片处理、任务暂存和 PDF 生成均在浏览器本地完成，不上传用户图片；外部错误日志不得包含图片、文件内容或完整本地文件名。文件解码前应限制类型、大小和像素尺寸，避免异常文件耗尽内存。
- **可访问性（NFR-3）**：上传、排序、旋转、删除、重试、模式切换、撤销/重做和导出均应有可聚焦控件、可见焦点和可读名称；状态不能只依赖颜色表达；文本和控件满足 WCAG 2.1 AA 对比度。精细画布笔刷操作可依赖指针设备。
- **可靠性与可观测性（NFR-4）**：每页采用独立状态（待处理、处理中、待复核、成功、失败、已取消）；错误应携带用户可理解的原因与可执行恢复动作。初版仅保留当前任务内的本地诊断信息，不接入包含用户内容的远程遥测。
- **兼容性（NFR-5）**：支持发布时最新两个稳定主版本的桌面 Chrome 和 Edge；不支持的浏览器应在导入前显示说明，而不是处理途中失败。
- **输出质量（NFR-6）**：PDF 页面为 A4 尺寸；“清晰”档优先满足打印可读性，“小文件”档允许降低图片质量但不得使基准样张中的正文在 100% 缩放下不可辨认。
- **擦除质量（NFR-7）**：在人工标注的代表性样张中，至少 80% 的黑色手写区域应被自动擦除，且至少 90% 的黑色手写区域应被自动擦除或正确标记为待复核；自动判定为已完成的页面不得丢失题干、选项、公式、表格线或插图中的关键印刷内容。蓝/红笔迹按不低于同一标准验收。

## 边界情况与失败行为

- 空选择不创建任务；超过 20 张时拒绝超出部分并保留前 20 张待用户确认。
- EXIF 方向应在裁剪和角度纠正前归一化；超大像素图应在保留可打印清晰度的前提下分级解码或缩放。
- 透明 PNG/WebP 在处理前应合成白色背景，避免导出 PDF 出现黑底或透明异常。
- 页面边界缺失、拍摄模糊、曝光过度或纸张被遮挡时，不伪造缺失题目；保留原图并标记待复核。
- 黑色手写与印刷内容颜色相同不能作为跳过识别的理由；系统应结合笔画和版面特征判断。手写与印刷字重叠或置信度不足时，优先保留内容并提示人工擦除；恢复笔必须能找回被错误擦除的原始像素。
- 浏览器内存不足、模型加载失败或单页解码失败时，释放该页中间数据并允许重试或跳过，其他页面不得丢失。
- 导出被浏览器拦截或磁盘写入失败时，任务和编辑结果继续保留，用户可重新导出。
- 刷新恢复时若本地数据不完整，应列出无法恢复的页面，不得静默生成缺页 PDF。

## 数据、接口、迁移与发布影响

- 初版无账号、服务端业务数据、公开 API 或数据库迁移。
- 浏览器本地任务模型至少包含：任务 ID、创建/最后活动时间、页面顺序、源图引用、处理状态、裁剪四角、增强配置、智能擦除遮罩、人工编辑遮罩、撤销信息和错误状态。
- 图像处理管线应将“页面解码、几何校正、增强、智能擦除、人工遮罩、PDF 渲染”定义为可替换阶段，便于后续增加 OCR 或临时云端推理而不改变用户任务模型。
- 首次发布采用小范围教师试用；保留关闭智能擦除、仅使用裁剪增强与手动工具的降级路径。由于无服务端持久化，回滚只需恢复上一版静态应用；新版不得未经提示破坏仍在 24 小时恢复期内的本地任务。
